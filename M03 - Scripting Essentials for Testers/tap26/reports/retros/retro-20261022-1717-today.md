## Root cause of the biggest problem (5 whys)
1. **Why did Bob still see $930.26 after Alice's $67 payment and a full reload?** The displayed profile balance was stale although the payment was complete and Bob's stored balance had increased to $997.26.
2. **Why was the displayed profile stale?** The reload restored a cached auth profile from localStorage and did not refresh Bob's profile from the API.
3. **Why was no profile refresh performed on that path?** The cached-state restoration path does not call the profile/check-auth refresh that the other path uses.
4. **Why did the first test not synchronize correctly?** It assumed reload would issue `GET /checkAuth` and waited for a request that the application did not make.
5. **Why was that assumption not caught earlier?** The reload path's actual network behavior was not established before choosing a response waiter, and there was no cross-user reload regression journey covering this state transition. Prevention: inspect the actual request flow first, then synchronize on observed behavior while retaining the outcome assertion.
